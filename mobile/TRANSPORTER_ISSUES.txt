Transporter / App Store Connect — issues & fix (no local Xcode)
===============================================================

ERROR YOU HIT (screenshot)
--------------------------
  Missing Provisioning Profile (90174)
  Apps must contain a provisioning profile in a file named
  embedded.mobileprovision.

Cause: the IPA dropped into Transporter was the UNSIGNED Sideloadly build
(GitHub release “Nexus iOS build N” / asset Nexus.ipa / tag ios-N).
Those builds intentionally omit embedded.mobileprovision so Sideloadly can
re-sign with your personal Apple ID.


Fix (cloud — no local Xcode)
----------------------------
1. Add Apple signing secrets once — follow mobile/APP_STORE_CI_SETUP.txt
   (Apple Distribution .p12 + App Store provisioning profile + ASC API key).

2. GitHub → Actions → “iOS App Store (signed)” → Run workflow
     • upload = true  → signs AND sends to App Store Connect (preferred)
     • upload = false → only produces Nexus-AppStore.ipa artifact

3. Use ONLY that artifact / release:
     tag:  ios-appstore-N
     file: Nexus-AppStore.ipa
   The workflow HARD-FAILS if embedded.mobileprovision is missing, so
   Transporter will not see 90174 on a green run.

4. Optional: website Apps → iOS apps shows “App Store (signed)” when a
   ios-appstore-* release exists.


Do NOT upload to Transporter
----------------------------
  • Nexus iOS build N / Nexus.ipa / tag ios-*
  • Wump / Browser / Link Sideloadly IPAs
  • Any IPA Sideloadly or AltStore re-signed for your personal Apple ID
  → always 90174 (or a different team / profile mismatch).


Other Transporter notes
-----------------------
• No icon while verification fails — expected; marketing icon is opaque RGB
  inside the signed IPA.
• Description / keywords / review notes are NOT inside the IPA — paste from
  mobile/app-store-listing.txt in App Store Connect.
• Xcode “not compatible” on an older Mac → ignore; CI uses macos-15.
